## Context

用户要求文本必须提炼，并让架构图仅在悬停模块时显示其前向与后向流向。已有报告为离线、零脚本 HTML/SVG。

## Goals / Non-Goals

- 默认只读要点；阻塞和重要问题完整列出；保留完整历史证据。
- 显示直接关联边，不展开传递调用链，不增加图形编辑器或模型调用。

## Decisions

1. 在新提交 schema 强制长度/行数，Skill 负责语义提炼；读取历史保持原上限。超限报错要求改写，不自动截断语义。
2. 原生 details 默认关闭。历史长文标为“原文预览”，可读完整源文；不把截断当摘要。
3. SVG 用内部数字索引和 CSS :has 关联模块与边，避免名称插入选择器。蓝色流入、绿色流出，箭头保持源→目标方向；同列连线绕到右侧。
4. 鼠标悬停优先于键盘焦点，避免混入另一个模块的连线。无悬停设备可聚焦点选；打印展示全部连线；尊重 reduced-motion。
5. scope/nextSteps 为可选字段，经 CLI/MCP 共用服务保留。按稳定 id 比较前后 revision，生成新增/更新/解决/移除数量；忽略对象键顺序，不伪造历史。

## Risks / Trade-offs

- 长度规则不能证明语义质量：Skill 明确要求结论、依据、代价，仍需人审。
- 旧资料若重新提交且超限，需要先准确提炼；原始快照不变。
- 交互依赖现代浏览器 CSS :has；无此能力时可展开文本依赖表。
- 多条同向依赖可能共享路径，原始依赖仍可展开查看。

## Validation

自动测试覆盖新旧 schema、错误路径、状态/历史、XSS、版本差异与服务回路；浏览器检查默认/关联边、焦点、窄屏；打包冒烟验证安装、CLI 与 MCP。

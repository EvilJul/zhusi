# 实施计划与验收标准

日期：2026-10-09。按可交付阶段推进，不预设开发工期。

## 阶段 0：验证产物是否有用

先手工用 Skill 流程完成一个小型预约系统设计，生成固定样例。检查用户能否在两分钟内找到核心业务、架构理由、下一步和未决问题。

验收：样例包含异常流程、至少一个有替代方案的决策、一个被拒绝的评审及理由；报告默认简短，细节可展开。
另做一个已有代码项目样例，验证用户能否在两分钟内回答“系统从哪里启动、一次请求怎样流转、模块为何这样依赖”。样例必须同时包含一个证据不足的未知项，并展示代码事实与架构意图的区别。

## 阶段 1：数据与 CLI（已实现基础，2026-10-10）

状态：已交付跨平台 CLI 基础（`init/status/validate/report/export/repair/explain` 与 `mcp` 启动边界）、`.zhusi/` 快照存储、项目锁、版本冲突与幂等、离线 HTML 报告、Markdown 导出和已有代码项目讲解快照。发布准备与支持矩阵见 [发布就绪说明](release-readiness.md)。完整 MCP 工具集与 Skill 适配仍在阶段 2。

实现 schema、快照存储、项目锁、版本冲突、幂等请求、init/status/validate/export；同时完成可安装的 npm CLI 包（`bin` 入口）。
同时实现架构讲解快照的 schema、代码 snapshot 指纹/提交号、来源证据和陈旧检测；不复制整个源码，不在筑思内自建代码索引。

验收：重复 init 不覆盖；损坏 JSON 明确报错；旧版本写入失败；重复 requestId 不重复提交；崩溃不破坏已有快照。覆盖并发写入、孤立快照、schema 升级拒绝与只读命令无副作用。
架构讲解验收：同一代码 snapshot 可识别重复请求；每条关键结论有文件/符号/配置证据；未读取范围显示 unknown；代码 commit 或目录指纹变化后旧讲解被标记陈旧；设计 revision 可为空。
跨平台验收：在 Windows PowerShell/cmd、macOS、Linux 上分别完成 `npx zhusi init` 与全局安装后的 `zhusi init`；验证 x64/arm64、路径空格、Unicode 路径、CRLF/LF、文件锁和报告离线打开。

## 阶段 2：MCP 与一个宿主适配

实现核心设计工具以及架构讲解工具，接入一个真实 AI 客户端。Skill 引导提问、方案解释、已有代码讲解与评审处置。

验收：真实客户端完成需求→提案→评审→修订；并能对一个真实仓库生成总览、调用链讲解和证据展开；stdin/stdout 协议不被日志污染；客户端重启后继续；上下文过大时明确分页或截断。

## 阶段 3：静态报告

实现摘要、图形、决策卡片、已有架构讲解、讨论折叠和打印样式。

验收：断网下直接打开；窄屏与键盘可用；来源版本可见；超长数据不隐藏重要未决项；恶意 HTML、script 闭合和 javascript 链接不会执行。

## 阶段 4：跨 AI 验证与公开分发

第二个 AI 客户端读取已有设计并评审；检查轮次、来源、版本以及修改是否可追溯。选择许可证并验证包名，准备安装与升级说明。

验收：不同客户端能顺序协作；同机并发冲突被检测；不依赖模型 API 密钥；安装包不含用户设计数据或密钥。GitHub 与 npm 发布分别进行明确验证。

## 后续可选

自动多模型讨论、超出证据范围的全面代码审计、OpenSpec 导出适配、SQLite 存储。设计与代码差异检查不再作为后续可选，而是已有架构讲解在存在设计 revision 时的基础能力。只有已有用户需求和实际瓶颈才启动。

## 第一版完成定义

- 一个 npm 安装包提供 CLI、MCP 和模板，并在 Windows、macOS、Linux（x64/arm64）可用。
- 至少一个真实宿主全流程验证，第二宿主验证异步评审。
- 可恢复、可追溯、可离线打开报告。
- 主要规则有行为测试；不把快照比对当作正确性证明。
- README 清楚区分已实现功能与未来计划。

# 实施计划与验收标准

日期：2026-10-09。按可交付阶段推进，不预设开发工期。

## 阶段 0：验证产物是否有用

先手工用 Skill 流程完成一个小型预约系统设计，生成固定样例。检查用户能否在两分钟内找到核心业务、架构理由、下一步和未决问题。

验收：样例包含异常流程、至少一个有替代方案的决策、一个被拒绝的评审及理由；报告默认简短，细节可展开。

## 阶段 1：数据与 CLI

实现 schema、快照存储、项目锁、版本冲突、幂等请求、init/status/validate/export。

验收：重复 init 不覆盖；损坏 JSON 明确报错；旧版本写入失败；重复 requestId 不重复提交；崩溃不破坏已有快照。覆盖并发写入、孤立快照、schema 升级拒绝与只读命令无副作用。

## 阶段 2：MCP 与一个宿主适配

实现 8 个核心工具，接入一个真实 AI 客户端。Skill 引导提问、方案解释与评审处置。

验收：真实客户端完成需求→提案→评审→修订；stdin/stdout 协议不被日志污染；客户端重启后继续；上下文过大时明确分页或截断。

## 阶段 3：静态报告

实现摘要、图形、决策卡片、讨论折叠和打印样式。

验收：断网下直接打开；窄屏与键盘可用；来源版本可见；超长数据不隐藏重要未决项；恶意 HTML、script 闭合和 javascript 链接不会执行。

## 阶段 4：跨 AI 验证与公开分发

第二个 AI 客户端读取已有设计并评审；检查轮次、来源、版本以及修改是否可追溯。选择许可证并验证包名，准备安装与升级说明。

验收：不同客户端能顺序协作；同机并发冲突被检测；不依赖模型 API 密钥；安装包不含用户设计数据或密钥。GitHub 与 npm 发布分别进行明确验证。

## 后续可选

自动多模型讨论、设计与代码差异检查、OpenSpec 导出适配、SQLite 存储。只有已有用户需求和实际瓶颈才启动。

## 第一版完成定义

- 一个安装包提供 CLI、MCP 和模板。
- 至少一个真实宿主全流程验证，第二宿主验证异步评审。
- 可恢复、可追溯、可离线打开报告。
- 主要规则有行为测试；不把快照比对当作正确性证明。
- README 清楚区分已实现功能与未来计划。
